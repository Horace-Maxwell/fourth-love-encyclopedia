# 版权与内容红线

> 全库都要守这一卷的**执行约束**。它护着三样东西：使用者能独立创作，使用者在法律上安全，这个库能长期用下去。
> 版本：v1.0

---

## 一、藏书提炼的红线

库里有一部分素材提炼自本地收藏的 **5,668 篇**作品（去重后的数，见 `10-藏书索引/藏书总索引.md`（本机私有不入库））。每一篇都有作者，都受著作权保护。所以库是这么做的：

### 1.1 可以做的：提炼**模式**

著作权保护的是**表达**，思想、方法、套路、体裁惯例这些不在保护范围内。这是对《著作权法》第五条和「思想／表达二分法」的通行理解。照这个理解，下面几类提炼既安全，也正当。

| 可提炼 | 例子 |
|---|---|
| 套路结构 | 「追妻火葬场」的五拍节奏与各拍篇幅占比 |
| 人设原型 | 「表面顺从、私下掌控实权的正君」这一原型的特征清单 |
| 世界观规则 | 女尊国的继承制度设计有哪几种常见解法 |
| 语感规律 | 女攻叙事中动词偏好短促、少用「轻轻地」这类副词堆叠 |
| 场景骨架 | 「初次交锋」场景的空间调度惯例，谁站着、谁坐着、谁先移动 |
| 数据统计 | 藏书中 np 与 1v1 的比例、各亚型的篇幅分布 |

### 1.2 不可以做的：搬运**表达**

| 禁止 | 说明 |
|---|---|
| 复制成段原文 | 一段都不行，改了几个字也不行 |
| 「洗稿式」改写 | 句式和顺序照原文，只换词，这就是侵权 |
| 大量短句拼接 | 从多篇各摘一段拼成"素材"，说到底还是复制 |
| 复制角色的完整设定 | 具体某个人物的姓名+身世+性格+关系网，整套组合起来就是受保护的表达 |
| 复述完整情节序列 | 一部作品从头到尾的情节链条，也受保护 |

### 1.2b 三类引号内容必须分清：这是本库合法性的地基

库里加了引号的成句内容分三类，法律上的性质完全不同。混在一起算，整个库看着会比实际危险得多：

| 类别 | 是什么 | 当期计数 | 依据 |
|---|---|---:|---|
| 作品原文 | 小说里的句子 | 30 处 | 按 1.3 的限度：每篇最多一句，要注明出处 |
| 社群言论 | 论坛发言、避雷帖、tag 说明、平台规则、科普问答 | 183 处 | 这些是研究对象，算不上文学作品。为了记录和评述而短引社群的话，做类型研究一向这么做 |
| 本库自撰 | 示范句、换皮示范、AI 版／人味版对照、口诀 | 22 处 | 编者原创，不涉他人权利 |

库里的引号内容大多是第二类，整个库的性质也由此定下：它记的是一个社群怎么谈论自己，提炼的是这个类型的结构规律，不把小说搬过来重新排一遍。作品原文只在讲某个具体技法、又没法用转述代替的时候才出现，一出现就注明出处，而且**同一部作品全库只引一句**。

> **写作时的操作规则**：凡是 ≥25 字的引号内容，下笔前先判断它是哪一类。
> - 第一类 → 必须带 `——《作品名》` 或 `（《作品名》第 N 章）`，引之前先查一下全库是否已经引过这部
> - 第二类 → 从上下文要看得出它出自社群（提到 tag／读者／平台／避雷／帖之类）
> - 第三类 → 在块的开头标上「示范」「例句自写」「自拟」
>
> [`_脚本/check_compliance.py`](../_脚本/check_compliance.py) 的 **I 项**会扫全库，
> 它报的是「像叙事散文、又没有出处也没有来源标记」的句子，真有风险的就是这种。
> 判断只看一条：这句像不像作品里的叙事文字。要是按「有没有标记」来判，误报会上百条。

### 1.2c 从语料自动提炼时的额外约束（13 卷）

[13-语料挖掘](../13-语料挖掘/) 里的东西是脚本从全部藏书正文里数出来的，人工把不住合规，规矩必须写进脚本。

| 约束 | 值 | 为什么是这个值 |
|---|---|---|
| 按独立作品挖，不按文件挖 | 2,897 部 | 「跨 N 篇即类型套话」能豁免，前提是这 N 篇来自 N 部不同的作品。语料里同一部作品常存了好几份（5,668 文件 ≈ 2,897 部），按文件挖的话，某一篇独有的句子靠自己的几份副本就能凑够篇数，混成套话。实测就这样漏过一条露骨的章节标题 |
| 逐字串上限 16 字 | 称谓实例、命令句 | 这么长只装得下「类型套话」，装不下「某位作者的表达」 |
| 跨作品下限 5 部 | 同上 | 同一句话在五部不同的作品里都出现过，就算这个类型的公共语法 |
| 首句不展示原文 | 开场句型学 | 每篇的首句只有一句，也不会在别的篇里重复出现，所以走不了「套话」这条豁免。这一节改成只给结构骨架 + 编者自写示范 |
| 章节标题 ≤12 字、剔露骨字面 | 章节标题库 | 只讲标题怎么起，具体的标题一个不列 |

这些阈值每一条都对应一次实测时漏掉的问题，都有来由。要动哪一条，先想清楚它当初挡的是什么。

### 1.3 引用的限度

必要时可引用，但严格限定：

- **单篇不超过一句**，要标清楚出自哪部作品
- 引用只为**说明某个技法**，不能拿来当素材库
- 引完必须跟分析，不能光放一句在那儿

### 1.4 精读笔记的特别约定

最容易越界的是一部一部写的精读笔记。约定如下：

- ✅ 写「这部作品用了什么手法、结构如何、原型是什么、亮点在哪」
- ✅ 写「它的第 N 章有一个转折，机制是 A 触发了 B」（描述机制）
- ❌ 写「第 N 章原文：……」（复制）
- ❌ 把梗概写到能替代阅读原作的详细程度

判断标准一句话：读完精读笔记的人应该学会一种手法，而不是知道了一个故事的全部内容。

原 09 卷那批笔记是一部一部拆的，就算每条都守住了四行约定，合起来还是接近梗概，读完就用不着再看原作了。这条判据是我自己定的，头一个没通过的就是这批笔记。文件还在，只是 `.gitignore` 把它排除了，不进仓库，所以下架归下架，本地的内容一点没丢。库里留下的是从笔记里提炼出的手法和规律，分散在 03–07 各卷，来源行写明是从哪几部作品精读来的。在本机，这条约定照旧有效。

## 二、创作独立性红线

这条管的是创作，不牵涉法律，一样得守。

要是用了这个素材库，写出来的东西越来越像库里的东西，这个库就是有害的。所以：

1. 库里的东西全是「零件」：原型只给骨架，套路只给节拍，角色和情节要自己写。

2. 每个条目都必须带「常见变体」和「写崩的三种方式」，为的是让使用者看清边界在哪，知道可以往哪里偏。

3. 「可直接粘贴的成段描写」不收。库里的「可直接用的素材」，只有钩子句、设定字段、状态板结构、世界书条目、开场白框架这几样。
4. 对待别人的作品，规矩跟本库对待藏书一样。桥段和套路属于公共层，谁都可以写「等门与热菜」。可具体到某一部作品，它的文字、情节编排、人物塑造都归作者所有。不抄袭，也不洗稿。换几个词、改几句、挪一挪情节顺序再发出来，照样是抄袭（判据见 1.2）。照着某本书的剧情走向「重写一遍」，哪怕一个字都没重合，也已经越线了。

5. **支持原版**。喜欢哪部作品，就去原发平台看、订阅、投票，能支持正版就支持正版。这个类型圈子小，全靠原创作者一直在写。素材库能做的是帮人写出自己的东西，哪一部真正的作品它都替代不了。

判据和精读笔记那条同出一源：从这里拿走的应该是一种手法，**而不是某本书的内容**。

### 2.1 参考外部素材：让写的人看不见它

常有这种活：手上有几张别人做得好的角色卡，或一批别人的设定，想参照着把自己的东西改好。这本身没问题，**拿走手法不拿内容**（判据同 1.2）。难在怎么确保真的没把内容拿走。光说「我注意一点」没用，嘱咐防不住，得从结构上防。

**结构上的办法：执笔的那一方根本看不到素材。**

素材由人来读，读完把手法抽成一份清单，清单里只有技法，不带内容，例子全是现编的。执笔的模型拿到手的是「我们自己的旧稿 + 这份清单」，素材它从头到尾没见过。没见过自然抄不了，光靠嘱咐「不许抄」是防不住的。

清单什么样，举两条用过的（2026-08 那轮重写角色卡用的）：

| 清单里的一条 | 它从素材里抽走的 | 它没带走的 |
|---|---|---|
| 外貌长在经历上：茧在哪个指节、是干什么磨的 | 「用身体细节交代来历」这个手法 | 素材里那个人是谁、磨茧的是什么活 |
| 想念藏在物件里，「他很想她」一个字都不许出现 | 「用物证代替情绪词」这个手法 | 素材里用的是哪件物证 |

**验收上的做法：指纹闸。**

写完不能光凭感觉说「没抄」。得从素材建一份指纹，逐个字段扫：

| 指纹 | 门槛 | 为什么是这个门槛 |
|---|---|---|
| 专名 | 零容忍 | 人名、地名、机构名、自造词，撞一个就是直接证据 |
| 八字连续片段 | 零容忍 | 八个字全同，白名单以外很难算巧合 |
| 六字连续片段 | 只看不拦 | 六个字容易撞上日常语（「根本不知道自己」这种），只当参考，不拿来判 |

**先扫基线。** 指纹建好，先拿它扫一遍现有仓库。基线里就有命中的，说明那几处是日常语撞上了，要先记下来放行，不然新写的东西会被自己的误报淹掉。2026-08 那次基线扫出专名 0 处、八字 7 处（「不知道自己为什么」这类），八字那几处进了白名单。

推之前，把推上去的那一份再扫一遍。本机扫过的不算数，要从远端重新克隆一份再扫。这和 fresh clone 验收一个道理，本机上总有只有本机才有的东西。

**参考发生在手法层。手法由人转述，转述之后，原文不该再出现在任何一个环节里。**

## 三、内容红线

### 3.1 绝对红线（无条件适用）

| 红线 | 说明 |
|---|---|
| 所有涉性内容中的角色必须是成年人 | 无一例外。设定年龄、外貌描述、身份（如「学生」）都不得暗示未成年。校园题材一律设定为大学及以上 |
| 未成年角色不与任何性内容关联 | 家庭题材、成长题材中出现的未成年角色，不涉入任何性描写、性暗示或性化描述 |
| 不收录真实人物的性化内容 | 同人涉及真人时，本库不提供任何相关素材 |

### 3.2 BDSM / 训诫类条目的附加要求

这类内容在本库中全谱系收录，但每一条必须附带**安全框架说明**：

- 现实 BDSM 实践的三套共识框架：**SSC（Safe, Sane, Consensual 安全、理智、知情同意）、RACK（Risk-Aware Consensual Kink 风险知情的自愿实践）、PRICK**（Personal Responsibility, Informed Consensual Kink）
- **虚构与现实的区分声明**：小说中的非自愿、无安全词、无事后照护等设定是幻想装置，不是现实实践指南。这一区分必须在条目中明确写出，不能默认读者知道
- 现实中能照做的危险行为，比如窒息、束缚、用药，只写它在故事里起什么作用，不写怎么操作

这样要求是出于实用。读者把幻想当成指南，会受伤。作者分不清两者，会把角色写成加害者，自己还意识不到，这个类型里这样写崩的很常见。详见 [06-尺度与写法/04-训诫与BDSM专论](../06-尺度与写法/04-训诫与BDSM专论.md) 第四节「『训练』与『施虐』的唯一开关」与第八节「虚构与现实的区分」。

### 3.3 幻想内容的立场

非自愿、囚禁、主奴、重口，所有亚型本库都收。这些东西在这个类型里本来就有，百科要做的是记全。收进来不等于提倡。具体做法：

- 全部打上预警标签，让使用者自己避雷
- 在条目里，「叙事功能」和「现实伦理」分开来写
- 不评判道德，也不美化

## 五、执行检查清单

### 5.1 能自动查的，一律跑脚本

有一次全库质量审计，查出 48 条问题，最严重的是这一类
「规约自己写了、但库里没做到」：五处高风险内容缺安全框架、
66 个结构单元缺「写崩的三种方式」、四篇卷首分级低于卷内条目。
这些问题想到不难，难在一条条去核。人工核一遍要一小时，脚本跑一遍几乎不费事。

```bash
python3 _脚本/check_compliance.py && python3 _脚本/sync_index.py --check
```

| 脚本 | 查什么 |
|---|---|
| [`check_compliance.py`](../_脚本/check_compliance.py) | 三行头齐备 ／ 分级就高不就低 ／ 高风险文件的安全框架（点名 SSC/RACK/PRICK + 虚构现实区分）／ 「写崩的三种方式」标题字符串统一 ／ 相对链接不失效 |
| [`sync_index.py`](../_脚本/sync_index.py) | 全库语料数字与 `aggregate_corpus.CANON` 一致 ／ 条数声明与实际一致，`--check` 只报不改 |

两个脚本都跑通了，再做下面几项人工检查。

### 5.2 只能人工核的

- [ ] 有没有成段原文被直接复制进来。改写过的搬运，脚本查不出来
- [ ] 本地精读笔记是否还停在「手法」这一层，没滑到「情节复述」里去
- [ ] 涉性条目里的角色，有没有都写明是成年人
- [ ] 事实性断言有没有来源。没来源的有没有标 `【待核实】`，标了的有没有写明试过哪些检索路径
- [ ] 新写的那三条「写崩的三种方式」，是否真只针对这个条目。脚本只能查有没有，查不出写的是不是废话
- [ ] INDEX.md 的完成度有没有同步更新

### 5.3 交付前的实测（不交「应该能用」的东西）

- [ ] 世界书 JSON **实际导入过**，还到书房数据库里查过实际生效的条数、常驻数，`chapter` 没有 NULL
- [ ] HTML 百科**在浏览器里打开过**，表格显示正常，全文搜索搜得到新加的内容
- [ ] 统计结论**抽样核验过**。中文语料里的高频词尤其要先怀疑是不是水印或编码问题
