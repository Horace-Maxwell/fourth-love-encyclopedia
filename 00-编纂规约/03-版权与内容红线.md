# 版权与内容红线

> 本卷是全库的**执行约束**。它保护三件事：你的创作独立性、你的法律安全、这个库的长期可用性。
> 版本：v1.0

## 一、藏书提炼的红线

本库有一部分素材，是从本地收藏的 **5,668 篇**作品里提炼出来的（去重后，见 `10-藏书索引/藏书总索引.md`（本机私有不入库））。这些作品都有作者，都受著作权保护。库的做法是：

### 1.1 可以做的：提炼**模式**

著作权保护的是**表达**，不是思想、方法、套路、体裁惯例这些。这是《著作权法》第五条和「思想／表达二分法」的通行理解。所以下面这些提炼，安全，也正当。

| 可提炼 | 例子 |
|---|---|
| 套路结构 | 「追妻火葬场」的五拍节奏与各拍篇幅占比 |
| 人设原型 | 「表面顺从、私下掌控实权的正君」这一原型的特征清单 |
| 世界观规则 | 女尊国的继承制度设计有哪几种常见解法 |
| 语感规律 | 女攻叙事中动词偏好短促、少用「轻轻地」这类副词堆叠 |
| 场景骨架 | 「初次交锋」场景的空间调度惯例，谁站着、谁坐着、谁先移动 |
| 数据统计 | 藏书中 np 与 1v1 的比例、各亚型的篇幅分布 |

### 1.2 不可以做的：搬运**表达**

| 禁止 | 说明 |
|---|---|
| 复制成段原文 | 一段都不行，无论是否改几个字 |
| 「洗稿式」改写 | 保持原文句式与顺序、只替换词汇，这是侵权 |
| 大量短句拼接 | 从多篇各摘一段拼成"素材"，本质仍是复制 |
| 复制角色的完整设定 | 具体人物，姓名+身世+性格+关系网的完整组合，属于受保护的表达 |
| 复述完整情节序列 | 一部作品完整的情节链条同样受保护 |

### 1.2b 三类引号内容必须分清：这是本库合法性的地基

全库带引号的成句内容有三类，它们的法律性质完全不同，混为一谈会让整个库显得比实际风险大得多：

| 类别 | 是什么 | 当期计数 | 依据 |
|---|---|---:|---|
| 作品原文 | 小说里的句子 | 30 处 | 受 1.3 的限度约束：单篇不超过一句，注明出处 |
| 社群言论 | 论坛发言、避雷帖、tag 说明、平台规则、科普问答 | 183 处 | 它们是研究对象，不是文学作品。为记录与评述而短引社群话语，是类型研究的常规做法 |
| 本库自撰 | 示范句、换皮示范、AI 版／人味版对照、口诀 | 22 处 | 编者原创，不涉他人权利 |

本库引号内容的主体是第二类，不是第一类。 这一点决定了整个库的性质：
它记录的是一个社群怎么谈论自己，提炼的是这个类型的结构规律，
而不是把小说搬过来重排。作品原文只在说明某个具体技法、且无法用转述替代时才出现，
出现即注明出处，且**同一部作品全库只引一句**。

> **写作时的操作规则**：任何 ≥25 字的引号内容，落笔前先判定它属于哪一类。
> - 第一类 → 必须带 `——《作品名》` 或 `（《作品名》第 N 章）`，且先查全库是否已引过这部
> - 第二类 → 上下文要能看出它来自社群（提到 tag／读者／平台／避雷／帖等）
> - 第三类 → 块首标明「示范」「例句自写」「自拟」
>
> [`_脚本/check_compliance.py`](../_脚本/check_compliance.py) 的 **I 项**会扫全库，
> 报出「像叙事散文、又没有出处也没有来源标记」的句子。那才是真正的风险项。
> 判据只有一条：这句像不像作品里的叙事文字。按「有没有标记」来判，会产生上百条误报。

### 1.2c 从语料自动提炼时的额外约束（13 卷）

[13-语料挖掘](../13-语料挖掘/) 是脚本从全部藏书正文里数出来的，合规不能靠人工把关，必须写进脚本。

| 约束 | 值 | 为什么是这个值 |
|---|---|---|
| 按独立作品挖，不按文件挖 | 2,897 部 | 「跨 N 篇即类型套话」的豁免，前提是那 N 篇是 N 部不同的作品。语料里同一部常有多份存档（5,668 文件 ≈ 2,897 部），按文件挖会让单篇的独特句子靠自己的副本凑够篇数、冒充成套话。实测漏过一条露骨章节标题 |
| 逐字串上限 16 字 | 称谓实例、命令句 | 这个长度把内容锁死在「类型套话」而非「某位作者的表达」 |
| 跨作品下限 5 部 | 同上 | 一句话在五部不同作品里都出现，它就是这个类型的公共语法 |
| 首句不展示原文 | 开场句型学 | 首句每篇只有一句，不跨篇复现，因此没有「套话」这条豁免路径。该节改为只给结构骨架 + 编者自写示范 |
| 章节标题 ≤12 字、剔露骨字面 | 章节标题库 | 这一栏的价值在命名法，不在列出具体标题 |

这些阈值不是拍脑袋定的，每一条都对应一次实测漏点。想动它之前，先想清楚当初它在挡什么。

### 1.3 引用的限度

必要时可引用，但严格限定：

- **单篇不超过一句**，出处作品名得标清楚
- 引它就是为了**说明某个技法**，不是给你当素材库用的
- 引完必须接分析，不能光摆一句在那

### 1.4 精读笔记的特别约定

逐部作品的精读笔记是最容易越界的地方。约定：

- ✅ 写「这部作品用了什么手法、结构如何、原型是什么、亮点在哪」
- ✅ 写「它的第 N 章有一个转折，机制是 A 触发了 B」（描述机制）
- ❌ 写「第 N 章原文：……」（复制）
- ❌ 把梗概写到能替代阅读原作的详细程度

判断标准一句话：读完精读笔记的人应该学会一种手法，而不是知道了一个故事的全部内容。

这批笔记（原 09 卷）的逐部拆解，就算每一条都守住四行约定，加起来也接近梗概，读者看完就不必再看原作。这条判据是我自己定的，结果第一个不通过的正是它。文件本身还在，只是被 `.gitignore` 排除了，不会进仓库，所以本地这批笔记虽然下架，内容并未丢失。库中保留的是从这些笔记里提炼的手法与规律，散在 03–07 各卷，来源行会注明具体是哪几部作品精读出来的。这一约定在本机继续有效。

## 二、创作独立性红线

这一条是创作要求，不是法律要求。分量不减。

一个素材库如果让你写出来的东西越来越像库里的东西，它就是有害的。所以：

5. **支持原版**。喜欢的作品去原发平台阅读、订阅、投票，能正版支持就正版支持。这个类型小，原创作者是它唯一的水源。素材库能做的是帮人写出自己的东西，替代不了任何一部真正的作品。

4. 对别人的作品，规矩和本库对藏书的规矩一样：桥段与套路是公共层，谁都能写「等门与热菜」。但任何一部具体作品的文字、情节编排、人物塑造，都归它的作者。不抄袭，不洗稿——换词改句、挪动情节顺序再发出来，仍然是抄袭（判据见 1.2）。照着某一本书的剧情走向「重写一遍」，哪怕一个字没重合，也已经越线。

2. 每个条目必带「常见变体」和「写崩的三种方式」，就是让使用者知道边界在哪、能怎么偏离。

1. 库里的所有东西都是「零件」不是「成品」。原型是骨架不是角色，套路是节拍不是情节。

3. 不收录「可直接粘贴的成段描写」。库里「可直接用的素材」就这些：钩子句、设定字段、状态板结构、世界书条目、开场白框架。这些是脚手架，不是墙。

一句话判据，和精读笔记的标准同源：从这里拿走的应该是一种手法，**而不是某本书的内容**。

## 三、内容红线

### 3.1 绝对红线（无条件适用）

| 红线 | 说明 |
|---|---|
| 所有涉性内容中的角色必须是成年人 | 无一例外。设定年龄、外貌描述、身份（如「学生」）都不得暗示未成年。校园题材一律设定为大学及以上 |
| 未成年角色不与任何性内容关联 | 家庭题材、成长题材中出现的未成年角色，不涉入任何性描写、性暗示或性化描述 |
| 不收录真实人物的性化内容 | 同人涉及真人时，本库不提供任何相关素材 |

### 3.2 BDSM / 训诫类条目的附加要求

这类内容在本库中收录，用户明确要求全谱系，但每一条必须附带**安全框架说明**：

- 现实 BDSM 实践的三套共识框架：**SSC（Safe, Sane, Consensual 安全、理智、知情同意）、RACK（Risk-Aware Consensual Kink 风险知情的自愿实践）、PRICK**（Personal Responsibility, Informed Consensual Kink）
- **虚构与现实的区分声明**：小说中的非自愿、无安全词、无事后照护等设定是幻想装置，不是现实实践指南。这一区分必须在条目中明确写出，不能默认读者知道
- 涉及现实可复现的危险行为，如窒息、束缚、用药等，只写叙事功能，不写操作细节

这一条图的是实用，不是道德姿态。一个把幻想当指南的读者会受伤，而一个分不清两者的作者会把角色写成加害者却不自知。后者恰恰是这个类型最常见的写崩方式。详见 [06-尺度与写法/04-训诫与BDSM专论](../06-尺度与写法/04-训诫与BDSM专论.md) 第四节「『训练』与『施虐』的唯一开关」与第八节「虚构与现实的区分」。

### 3.3 幻想内容的立场

本库收录非自愿、囚禁、主奴、重口等一切亚型。它们客观存在于这个类型中，百科的职责是完整记录。收录不等于提倡。做法是：

- 全部打预警标签，使用者自行避雷
- 条目里把「叙事功能」和「现实伦理」分开写
- 不评判道德，也不美化

## 五、执行检查清单

### 5.1 能自动查的，一律跑脚本

一次全库质量审计查出 48 条问题，其中最严重的一类是
「规约自己写了、但库里没做到」：五处高风险内容缺安全框架、
66 个结构单元缺「写崩的三种方式」、四篇卷首分级低于卷内条目。
这些都不难想到。难在没人逐条核过。人核一次要一小时，脚本核一次零成本。

```bash
python3 _脚本/check_compliance.py && python3 _脚本/sync_index.py --check
```

| 脚本 | 查什么 |
|---|---|
| [`check_compliance.py`](../_脚本/check_compliance.py) | 三行头齐备 ／ 分级就高不就低 ／ 高风险文件的安全框架（点名 SSC/RACK/PRICK + 虚构现实区分）／ 「写崩的三种方式」标题字符串统一 ／ 相对链接不失效 |
| [`sync_index.py`](../_脚本/sync_index.py) | 全库语料数字与 `aggregate_corpus.CANON` 一致 ／ 条数声明与实际一致，`--check` 只报不改 |

两个脚本都通过之后，再做下面这几条人工检查。

### 5.2 只能人工核的

- [ ] 有没有成段原文被直接复制进来，脚本查不出改写式搬运
- [ ] 本地精读笔记是不是还停在「手法」层面，没有进到「情节复述」
- [ ] 涉性条目里的角色，是不是都明确写了成年
- [ ] 事实性断言有没有来源，或者标了 `【待核实】`，标了的话有没有写明试过哪些检索路径
- [ ] 新写的「写崩的三种方式」三条，是不是真的只针对这个条目，脚本只能查有没有，查不出是不是废话
- [ ] INDEX.md 的完成度有没有同步更新

### 5.3 交付前的实测（不交「应该能用」的东西）

- [ ] 世界书 JSON **实际导入过**，并查了 D1 生效条数、常驻数、`chapter` 无 NULL
- [ ] HTML 百科**在浏览器里打开过**，表格渲染正常、全文搜索命中新增内容
- [ ] 统计结论**抽样核验过**：尤其是中文语料里的高频词，先怀疑是水印或编码问题
